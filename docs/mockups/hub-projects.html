Status hub projects menu

The menu on the left is the hub's whole navigation, and today every project takes two lines: its name and blocks, then its progress and the age of the last upload. Seven projects already run past the page they sit next to, and nothing on the menu says which one is opened daily and which one was abandoned in September. The update marks projects as favourites, folds them into groups and moves the progress into a card that opens on hover. The three arrangements below all carry those three ideas and differ in what stays on screen — the list, the row, or the column.

A — Favourites pinned, groups fold in place

row 32px · a caption per group

A star at the end of the row, shown on hover or focus, pins a project into a Favourites block above the list, and a star is a property of the project, not a copy: a starred project leaves its group, so it appears once. Groups are captions with a chevron and a count, folded independently and remembered per admin; the group a project belongs to is set where the project is edited. The second line is gone — the summary waits in a card that opens when the pointer rests on the row's block icons, or when they take keyboard focus.

Trade-off: nothing is hidden and nothing is reordered, so the column is still exactly as tall as its projects — a fourth group would push Manage projects below the fold.

B — One line per project, a dot for freshness

row 24px · no block icons in the row

The row keeps a name and a dot — green for an upload today, yellow once it is older than a day, grey for a project that never uploaded — and gives up the block icons to the card. Trade-off: the blocks a project has are no longer visible at a glance, and the freshness dot asks a reader to learn three colours before it means anything.

C — A rail of marks that opens on hover

column 56px · menu 248px over the page

Phone — the shared Dropdown

Rooftops

Below 960px the menu is the shared Dropdown and stays one: favourites sort first, groups fall back to the list's order, and there is no hover card — the project page already shows its progress. Showing groups in the list needs a header item type in Dropdown, which this proposal does not ask for.

Colours, spacing and radii are the project's own tokens: the :root block above is generated from apps/web/src/lib/app/styles/vars by bun --filter web sync:tokens. The typeface is substituted — Hanken Grotesk stands in for ApercuPro, whose licensed file cannot be served from a third-party host. Every icon is the site's own Svg* component; no new glyph is proposed. B shipped, and its row height and dot size are the site's --status-menu-row-height and --status-menu-dot-size; --mock-row-height, --mock-rail-width and --mock-mark-ring remain proposals. The hover card is portalled in the build, so it is drawn here inside the row to keep its anchor obvious.
