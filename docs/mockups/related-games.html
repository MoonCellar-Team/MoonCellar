Related games

The API already stores relatedGames: nineteen IGDB/VNDB relation fields, each an array of game ids. The page shows none of it yet. Four ways to surface it, each drawn in place on the game page so its weight against the other blocks is visible. Dashed blocks are the existing sections; the outlined one is new. Every variant folds the nineteen fields into the same five groups.

A

Shelves by group, under Media

A full-width box between Media and Details. Each non-empty group is a horizontally scrolling row of covers with the relation under the title. Empty groups disappear, so a standalone game with only similar titles gets a single shelf. The tallest option: with all five groups it is longer than Media itself.

B

Tabs with a cover grid, under Details

One group at a time, placed after Details and before Community, where the page turns from facts about the game to browsing. Tabs carry counts, so the size of each group is visible before clicking. Height stays close to one row of covers regardless of how many relations the game has.

C

Series line and add-ons, above Media

Story relations ordered by release year, current game highlighted, directly under the overview row: where a game sits in its series is read together with its description. Add-ons follow as compact rows with the user's status dot. Versions, Universe and Similar sit behind “All related”, which opens A or B lower on the page.

D

Compact list in the side column

No new full-width section: the list joins GameSideColumn under External pages and Links. Grouped rows with a small cover, year and relation, five rows by default and the rest behind “Show all”. Cheapest on layout, but it stretches the overview row when expanded and the covers are too small to recognise unfamiliar games.

Block order follows GamePage.tsx: Hero, the Overview · Score · Side row, Media, Details, Community, then Release dates · Multiplayer. Ghost heights are approximate.

Rendering needs the related documents, not ids: title, slug, cover, release year and, for a signed-in user, their status. One batched lookup on the game endpoint covers all variants; the ids are already on the game document.

Colours, spacing and radii are the project's own tokens, generated from apps/web/src/lib/app/styles/vars by bun --filter web sync:tokens. Covers are gradient placeholders. Hanken Grotesk stands in for ApercuPro.
