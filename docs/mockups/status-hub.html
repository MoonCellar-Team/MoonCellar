Project status hub

A private site at status.mooncellar.space where admins follow every MoonCellar project: sign in with a MoonCellar account, pick a project from the menu, read its page. A page is built from the blocks the project publishes — a plan of tasks, decompilation progress, or both — so a new project needs data, not a new screen. It replaces the static page behind a browser password.

Sign in
The site's own account, through the shared sign-in form. The cookies are the ones mooncellar.space already uses.
Admins only
GET /admin/access decides; anyone else sees "No access", not the data.
Pick a project
The menu lists every project with the blocks it has and when it last uploaded.
Read its blocks
Plan and Decompilation render from JSON the project uploads with its own token.

What gets built

Pages in apps/web, served by host

The hub is a route group of the existing app, answered for status.mooncellar.space only, so it uses the shared UI kit and the site's sign-in. No new container.

API module projects

PUT /projects/:slug/data/:block with the project token; GET and project management behind the admin role. Blocks are stored as the JSON the project sent.

Two block types

Plan: sections of tasks with id, title, state, owner, waits-for, size. Decompilation: totals, categories, areas, the function map, files and the feed.

No browser password

nginx proxies the host to the app; the basic-auth file and the static folder on the server go away.

Colours, spacing and radii are the project's own tokens: the :root block above is generated from apps/web/src/lib/app/styles/vars by bun --filter web sync:tokens. The hub's own sizes and the pending-merge colour shipped as --status-* tokens in vars/_components.scss. No new icons. The typeface is substituted — Hanken Grotesk stands in for ApercuPro, whose licensed file cannot be served from a third-party host.
