Profile Overview

Three layouts for the first tab of a profile, now that it has to carry more than an avatar and a feed: five favourite games, custom lists, an activity history that can be read at a glance, and follower counts that no longer grow into a wall of avatars. Every example is drawn for the invented profile moth_scholar; the favourites heart and the lists popover are in the Game Controls mockup, the list page in Custom Lists.

Placement
/user/[name], the default profile tab inside the content Box. UserNavigation stays on the right and gains a Lists panel.
Already stored
Avatar, background, a Markdown description of up to 450 characters, follower and following ids, activity logs merged per game, playthrough counts.
New data
user.favorites — up to five game ids in the owner's order, set with the heart in GameControls. Custom lists live in their own collection.
What breaks today
Every follower avatar is rendered; one activity entry is a full GameCard plus a card of text, so ten entries fill three screens.
A

Favourites shelf

Identity in one row, then the five favourites as the largest thing on the page — they are the one part of a profile the owner chose by hand. Activity turns into a dense day-grouped feed on the left, lists sit beside it as cards. Followers collapse into two counters with a face stack; the full list opens in the drawer.

Settings

Works for

  • Identity and games never compete for width; favourites and tiles get the whole wide column.
  • Follower faces are always visible but capped at five plus a counter.
  • A filter on activity is cheap here: the log type field already exists.

Costs

  • Three columns on desktop (identity, games, navigation) — the wide column is about 700px at 1440.
  • On a phone the identity column becomes a header, which is variant A again.
  • The stat facts need a new aggregate (hours, completed count) on the profile response.
C

Banner and ranked five

The profile borrows the game page's hero: the user's own background becomes a banner inside the panel, the avatar overlaps it, and counters sit in tiles like "Beaten by" on a game. Favourites are ranked — number one is drawn larger — which only makes sense if the owner's order is meant to be read. Activity becomes a timeline whose dots take the category colour.

  • The most personal first screen: the user's background finally appears inside the panel, not only behind it.
  • The timeline reads as sentences ("Dropped Signalis"), the closest to how people describe what they did.

Costs

  • The banner doubles the background: BGImage already shows it behind the page.

How it would be built

Whichever layout wins, the data work below is the same. It is listed so the choice can be made on the drawing, not on hidden cost.

API · user

  • favorites: ObjectId[] on User, declared with type: mongoose.Schema.Types.ObjectId, ref: "Game" so string ids cast; at most five, validated in packages/schemas.
  • PATCH /user/:id/favorites takes the whole ordered array — reorder, remove and replace are one request.
  • The profile response returns favourites populated with name, slug, cover, plus followersCount, followingsCount and the first five of each instead of the full arrays.
  • GET /user/:id/followers?page= and /followings feed the drawer.

API · activity

  • renderLogText already splits segments; the logs endpoint additionally returns segments: [{ kind, status?, platform?, time?, date?, rating?, list? }], parsed from the fixed Status / Console / Date / Time labels — old rows parse the same way, nothing is migrated.
  • One new segment kind, favorite, written by the favourites service through createUserLog, so it merges per game like the others. Lists never write a log.
  • A segment that does not parse keeps its text and renders through RichText.

Web

  • UserInfo splits into ProfileHeader, FavoriteGames, ActivityFeed and PeopleDrawer; all render on the server so the profile HTML carries the favourites and the first page of activity.
  • UserNavigation gains the Lists panel; the unfinished CustomFolder modal and its Edit row are removed.
  • Pagination stays on the shared Pagination; log deletion keeps ConfirmModal.
  • Drag reordering needs a small pointer handler of our own or a dependency — to be decided; the arrow buttons work without it.

New tokens and icons

  • Tokens to promote into vars/_components.scss: --mock-profile-avatar, --mock-profile-avatar-sm, --mock-activity-cover, --mock-people-avatar, --mock-nav-width; C also --mock-hero-height.
  • The favourite colour is --color-pink, which is also --game-backlog-color — a --favorite-color alias keeps the two separable.
  • New Svg* components: SvgLock (private lists), SvgGrip (drag handle), a filled state for SvgHeart, SvgMinus.

Colours, spacing and radii are the project's own tokens: the :root block above is generated from apps/web/src/lib/app/styles/vars by bun --filter web sync:tokens. Covers and avatars are gradient placeholders; the backdrop behind each frame stands in for BGImage. The typeface is substituted — Hanken Grotesk stands in for ApercuPro, whose licensed file cannot be served from a third-party host.
