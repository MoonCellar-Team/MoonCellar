Expanding Long Content

Every long block on the site — a review, a game summary, a wall of keywords — is clamped by ExpandableBlock, and the only way to read the rest is a modal. These are the ways to open it without leaving the page: in place, by scrolling, or a mix. Each variant is drawn twice, on a review and on the game page's Summary and Keywords, because those are the two shapes the component has to serve.

Where it is used
Reviews on the game page and on the profile, Summary, Storyline and Keywords in GameOverview, the gauntlet winner panel.
Today
Clamp to --community-review-clamp-height (132px) or four lines, then Show more opens the whole text in a modal.
Must hold
The full text stays in the server HTML — collapsing is CSS, never slice(). Scroll areas use the shared Scrollbar.
Reality check
Most notes are two or three lines and never clamp at all; the pattern only shows up on the long ones.
A

Expand in place

Show more grows the block itself and pushes everything below it down; Show less puts it back. No layer, no navigation — the review stays in the feed you were reading, and the next review moves out of the way. Try both toggles below.

Works because

  • Reading never leaves the page: no layer opens, nothing has to be closed, the scroll position is where you left it.
  • One state, one toggle — the same control collapses the block again.
  • Works for both shapes: a wall of text and a grid of keyword chips.

Costs

  • A very long note — and reviews can be a screen tall — pushes the rest of the feed far down, so the next review is a scroll away.
  • Animating max-height to a guessed value is jumpy; it has to be measured (scrollHeight).
  • Collapsing a block you scrolled past leaves the viewport in the middle of nowhere unless the toggle scrolls the block back into view.
B

Scroll inside the block

Nothing expands at all. The block keeps its height and the long text scrolls inside it, with the shared Scrollbar. Every row in the feed stays the same size, so the list stays scannable no matter how much someone wrote. Scroll the two blocks below.

C

Expand in place, then scroll

A and B in one control. Show more grows the block, but only up to a cap — a third of the viewport. A note that fits under the cap is simply open; one that does not keeps scrolling inside the expanded block. The feed below never gets pushed more than one screen.

Bottom sheet · the phone fallback

What the page pays

  • Inside the panel (top): the feed drops to about 55% of its width, so a review row loses roughly 300px — covers, status and rating stay, the excerpt gets two lines instead of four.
  • Docked to the window (bottom left): the feed keeps its width but the panel covers the right half of everything, including the blocks the reader was not looking at.
  • On a phone neither fits: the panel becomes a bottom sheet, which is variant D with a nicer gesture.

What it buys

  • Reading three reviews in a row is three clicks and no closing, against six actions with the modal.
  • The list keeps its scroll position and its filters — the panel is the only thing that changes.
  • The open review can sit in the URL, so a link opens the page with that review already in the panel.
G

No clamp at all

Print everything. No control, no state, no component — the card is as tall as the text. Worth putting on the table because the median note is two or three lines: the clamp exists for a minority, and every variant above is machinery bought for that minority.

Works because

  • Nothing to build, nothing to measure, nothing to animate — ExpandableBlock disappears from these call sites.
  • Every word is visible to a reader and to Ctrl+F, with no state in between.
  • Honest about the data: most notes are short, and the long ones are the reason people open a review section at all.

How it would be built

All four are one component with one prop; nothing at the call sites changes except that prop.

Component

// shared/ui/ExpandableBlock
mode:
  | "inline"   · A
  | "scroll"   · B
  | "capped"   · C
  | "modal"    · D, default
  | "none"     · G
clampHeight?: string
expandedHeight?: string
modalTitle?: string
group?: string  · E, one per group

Default stays "modal", so every existing call site keeps its behaviour until it is switched over one at a time.

Mechanics

  • Open height comes from scrollHeight measured by the existing useResizeDetector, not from a guess, or the animation stutters.
  • Animate max-height with --duration-base / --easing-out; under reducedMotion drop to --duration-instant, never none.
  • The fade at the bottom is a gradient to --color-bg-primary and must vanish when open.
  • Collapsing scrolls the block back into view if its top is above the viewport.

Scroll areas

  • "scroll" and the capped state of "capped" render the shared Scrollbar — a native scrollbar does not match the theme.
  • overscroll-behavior: contain so the page does not start scrolling when the block ends.
  • The container needs min-height: 0 for the flex chain, as Box already does.

Where each fits

  • Reviews (game page, profile): C — one click, bounded push; E if the feed still feels long.
  • Summary and Storyline: A — a paragraph or two, nothing to cap.
  • Keywords: A — the grid is meant to be seen whole.
  • Gauntlet winner panel: B — the panel has a fixed height by design.
  • Short notes everywhere: G — below the clamp the component renders nothing extra anyway.
  • F only if reading many reviews in a row becomes a real use case; it is a layout, not a prop.

Recommendation

Ship C for reviews and A for the game page; keep E and F in reserve

The modal is doing a job that the card can do itself: two extra paragraphs do not deserve a layer. Adding mode to ExpandableBlock is a day's work and can be rolled out one call site at a time, because the default keeps today's behaviour. E is a second flag on top of C and only pays off once feeds are long enough to feel it; F is a different screen, worth building the day someone reads reviews in a row rather than one at a time. G is the honest baseline to measure the rest against — if the clamp fires on one note in fifty, most of this machinery is optional.

Colours, spacing and radii are the project's own tokens: the :root block above is generated from apps/web/src/lib/app/styles/vars by bun --filter web sync:tokens. The typeface is substituted — Hanken Grotesk stands in for ApercuPro, whose licensed file cannot be served from a third-party host. The scrollbars here are the browser's own, styled to match; on the site every scroll area is the shared Scrollbar. Covers are coloured placeholders and the reviews are invented.
