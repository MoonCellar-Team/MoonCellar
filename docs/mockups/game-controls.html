Game Controls

The small bar under every cover gets two new buttons: a heart that puts the game into the player's top 5, and a list button that files it into lists the player made themselves. What is being decided here is how a pressed button reads when four of them share a bar 124 pixels wide, and what opens when the list button or a sixth heart is pressed. Everything is drawn for the invented profile moth_scholar.

Placement
GameControls — under the cover in the game page hero, and at the bottom of the overlay a GameCard opens with “…”.
Data assumed
user.favorites: ordered, at most 5 game ids. Lists are their own collection — name, description, isPrivate, ordered games[] with addedAt — each at /user/<name>/lists/<slug>.
Must have
One press adds or removes a favourite. The list button shows the player's lists with this game's ones checked, and a list can be created without leaving the page.
Reality check
The card overlay is 140–200px wide and already holds two buttons. Guests see the same bar on 10 000 server-rendered game pages.

The new bar

Order goes from the player's own record to the outside world: what they played, what they love, where they filed it, then links to other sites. The last button changes its icon — with a list button beside it, today's three-line menu glyph would read as a second list.

A

Accent fill, one rule for the bar

A pressed button fills with the accent, exactly as Playthroughs already does, and the heart also turns solid so the state holds without colour. The bar keeps a single rule — filled means this game is yours in that way — and nothing new has to be learned. The cost shows on a game the player loves: played, favourite and listed turn three of four buttons purple, and the bar becomes the loudest thing on the card.

B

Coloured glyphs on a quiet bar

No button fills any more, Playthroughs included: every state lives in the glyph. Playthroughs takes the colour of the game's status — green for completed, yellow for mastered, the colours the card already glows in — with a badge once there is more than one playthrough. The heart turns solid pink, and the list glyph takes the accent with a badge counting the lists. One rule for the whole bar, calm on any cover, and it says more than A: which status, how many playthroughs, how many lists. The cost: today's accent fill on Playthroughs disappears from every card on the site, the state rests on a 20px glyph, and pink is also the backlog colour.

Behaviour

  • Rows keep their order while the popover is open — a list that just gained the game does not jump under the cursor. Next time, lists are ordered by last change.
  • The count includes this game, so it moves as the row is checked.
  • Closing the popover sends one toast summing up the change, never one per click.

Phones

  • Below mediaMd the button opens modal.open with the same body. A 320px popover anchored to a 28px button leaves no room for a thumb.
  • Rows grow to 44px tall there; the filter keeps the keyboard from covering the list.

Private lists

  • A lock marks lists only the owner sees, in the popover and on the profile.
  • New lists start public. Privacy and the description are set on the list page, so creating one here stays a single field.

When the top 5 is full

A sixth heart does not fail with an error. It opens a small popover over the button: pick the favourite to give up, and the new game takes its place in the order. Reordering the five belongs to the profile, not here.

How it would be built

Both variants share every piece below; they differ in about ten lines of GameControls.module.scss.

Web · components

  • GameControls gains FavoriteButton and ListsButton between Playthroughs and the menu; the menu switches to SvgMore with the tooltip “External links”.
  • In B, Playthroughs drops controls__action_active: it reads the game's playthroughs from parsedPlaythroughs, picks the status by playthroughPriorityOrder (mastered wins), colours the glyph with that --game-*-color and shows the count from two up.
  • features/lists/ui/ListsPopover on the shared Popover; the same body goes through modal.open on phones.
  • features/favorites/ui/FavoritesFullPopover for the sixth heart.
  • Rows use the shared Checkbox, the long list Scrollbar, the name field Input.
  • The 20px icon under 150px is an @container rule, as GameCardInfo already does for its text.

API

PATCH  /user/:id/favorites        { gameIds } ≤ 5, order kept
GET    /user/:id/lists            ?gameId= → lists + contains
GET    /user/:id/lists/game-counts { [gameId]: n }
POST   /lists                     { name, gameId? }
POST   /lists/:id/games           { gameId }
DELETE /lists/:id/games/:gameId

One PATCH with the whole array covers add, remove, swap and the profile's reorder. favorites is declared type: [ObjectId], ref: "Game" — a bare ref makes a Mixed path and string ids silently stop matching. The limit of 5 lives in the shared zod schema. Private lists are returned to their owner only.

Queries · optimistic updates

  • Favourites ride on the signed-in profile, so the heart renders without a request; the mutation patches the profile first and rolls back with the error toast.
  • ["lists", userId, "game-counts"] loads once per session, like parsedPlaythroughs — a grid of 30 cards must not ask 30 times which lists hold each game.
  • ["lists", userId, { gameId }] loads when the popover opens; each checkbox updates it with setQueryData, then invalidates the counts and the list page.

Guests and server rendering

  • Game pages are ISR: the bar renders the same HTML for everyone, and pressed states appear after hydration from client stores. Nothing reads cookies or search params in the route for it.
  • No request for a guest: every query here is enabled: !!profile?._id, and ListsPopover is loaded with next/dynamic on first open.

Icons and tokens

  • SvgHeart gets a filled prop — same path, fill instead of stroke.
  • New SvgLock for private lists. No check glyph: the site's round Checkbox fills with the accent.
  • To promote into _components.scss: --mock-ctl-icon-size, --mock-ctl-icon-size-sm, --mock-top5-cover-width; B only: --mock-list-badge-size (shared by both badges), --mock-favorite-color; Playthroughs takes the existing --game-*-color tokens.

Recommendation

Variant B

With Playthroughs moved to a coloured glyph, B no longer mixes two rules, and it carries more than A on the same four buttons: the game's status, how many playthroughs, how many lists — while a played, loved and listed game keeps a quiet bar instead of three purple blocks. What to watch when it is built: the 140px card, where the state rests on a 20px glyph, and backlog games, whose pink Playthroughs glyph sits next to the pink heart. A is the fallback if the small card proves unreadable.

Colours, spacing and radii are the project's own tokens: the :root block above is generated from apps/web/src/lib/app/styles/vars by bun --filter web sync:tokens. The typeface is substituted — Hanken Grotesk stands in for ApercuPro, whose licensed file cannot be served from a third-party host. Covers and artwork are coloured placeholders; the profile, its lists and favourites are invented. Icon paths are copied from shared/ui/svg, except the lock, which does not exist there yet.
