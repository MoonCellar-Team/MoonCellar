Getting to the viewer page

The host page owns the viewer link but nothing opens it. Checking what the other admin sees — a wrong surface, a stream that arrived silent — means copying the URL into a new tab. Four places to put that way out, each drawn at the sidebar's real width, next to the link that already exists.

Option A · shipped

Open in the same row, as an icon

A square icon button next to the field, in front of "Copy link", carrying the open-window glyph that already exists as SvgOpenWindow. The sidebar was widened from 1.65fr to 1.5fr of the page so the 51-character link still fits on one line; below roughly 1300 px the two actions move to a second line together instead of breaking the URL.

  • One click from the place the URL already lives, no new line in a dense panel.
  • Costs the preview about 30 px of width, and the field about 40 px — which is why the sidebar had to grow.
  • An icon alone has to be learned; the tooltip carries the meaning.

Option B

The link is the link

The field itself becomes an anchor opening the viewer page in a new tab, with the open-window glyph at its right edge and an accent border on hover. No new control at all — the panel stays exactly as tall as it is.

  • Zero extra weight; the URL is where the eye already goes.
  • A read-only looking field is suddenly clickable, and selecting the text to copy it by hand navigates away instead.
  • Needs the glyph and a hover state to be believable — a bare underline is easy to miss.

Option C

Two buttons under the field

The field keeps the full width of the panel, and the two things the host can do with it sit on a row of their own: copy it, or open it. Both are the same weight, both are text, both are 40 px tall — no icon to decode.

  • Reads without instructions, and the link stops wrapping against the buttons.
  • Costs one row in the sidebar, which scrolls anyway.
  • At phone width the two buttons stay side by side and stay tappable.

Option D

Down with the session actions

"Open viewer" joins the row under the stage, next to "Share another screen", "Stop stream" and "Remove viewer" — the actions that belong to the running session rather than to the invite.

  • Uses a row that already wraps and has space.
  • Two steps away from the link, and the row sits under the preview, not beside the invite where the host looks first.

What the control does in every option

  • Opens/admin/stream/watch/<code> in a new tab, because leaving the host page ends the room. The page only prefills the code — joining is still a click of "Watch stream" there, so opening it does not disturb the room.
  • One viewer, one roomIf the host joins their own stream they take the room's only viewer slot, and a real viewer then gets "Someone is already watching this stream." The button stays enabled: that refusal comes from the room, not from the control.
  • No code, no linkUntil the room exists the button is disabled, exactly like "Copy link" today; its href falls back to the watch page, where a code can be typed.
  • Sound before the screenThe audio input is a separate control: it can be chosen before anything is shared, waits for the capture, and survives "Share another screen". Its mute toggle only appears while a stream is live.
