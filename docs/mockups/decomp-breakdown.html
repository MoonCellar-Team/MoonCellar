MoonCellar · decompilation breakdown

Categories and Areas, connected

The decompilation block measures the same work on two axes: categories split every function by the module it builds into, areas split the files people have claimed. The panels used to sit side by side and never say how they relate; the block now opens the areas inside their module (Option A below, shipped). Option B is kept as the alternative that was not taken.

Category

The module a function builds into — game, sdk, lib. Every function has exactly one, so the rows add up to the totals above.

Area

A slice of work declared by hand in the project, with a lead. A file may have no area at all, so areas never add up to the totals.

Gains The relation is visible in one panel, and the empty modules make the coverage of the area split obvious.

What it takes

  • No schema change. Every uploaded unit already carries category and area, so both the tree in A and the per-module counts in B can be derived from decomp.units; titles, leads and done counts still come from decomp.areas.
  • A needs a sub-row list inside the Categories panel; B needs a Tabs theme="segmented" in the Areas header. Neither touches the map, the feed or the upload format.
  • Whichever ships, the Areas empty state should name where areas come from, as in the fourth state above — an empty filter otherwise reads as a bug.

Colours, spacing and radii are the project’s own tokens: the :root block above is generated from apps/web/src/lib/app/styles/vars by bun --filter web sync:tokens. The typeface is substituted — Hanken Grotesk stands in for ApercuPro, whose licensed file cannot be served from a third-party host.
