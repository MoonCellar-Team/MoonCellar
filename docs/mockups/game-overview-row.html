Game page overview row

Under the hero, Summary, the score column and the links column sit in one row, and all three panels stretch to the tallest. Inside the shorter ones the blocks are pushed apart (justify-content: space-between, Keywords pinned to the bottom), so a game with lots of scores opens holes in the middle of the other two. Four ways out, each drawn at desktop width for a short game (the one from the report) and a long one.

Current

Equal-height panels with their blocks spread to the top and bottom edges.

A · Pack to the top

Same three panels and the same height, but blocks stack from the top. Spare height collects at the bottom of the shorter panels.

  • Three lines of CSS; nothing moves.
  • No holes between blocks, but a long column still leaves an empty foot under the others.

B · Scores in a row, text below

Ratings, HowLongToBeat and Achievements become one row of equal panels: they hold the same kind of content (one to four short rows), so stretching them leaves at most a row or two of space at the foot of the smallest. Text and links follow in a second row where each panel keeps its own height.

  • Like sits next to like, so equal heights look right instead of leaving holes.
  • With fewer than three score panels, the links panel moves up into the row to fill it, and Summary takes the full width below. With none, the row is skipped.
  • Numbers come first, right under the hero's counters; the summary moves one row down.
  • The blocks already render boxed (isBoxed defaults to true); the row is a grid that takes two to four panels.

B · When scores are missing

Many games have no HowLongToBeat entry or no achievements. The row never keeps an empty slot: the links panel takes it, and Summary drops below at full width with its text kept to a readable measure.

Shipped

C · Text with a sidebar

A wide text column (summary, then stores and links) and a sidebar as wide as the hero's counters above it (scores, then followings). Each column stacks its own panels.

  • Lines up with the hero: the sidebar continues the counters column.
  • A short summary next to a long sidebar still ends early; the gap moves outside the panels instead of inside them.

D · Balanced columns

Every block becomes its own small panel, and CSS columns flow them into three columns of nearly equal height.

  • The browser balances the heights for any game, with no rules per block.
  • Where a block lands depends on the game, so Ratings is not always in the same place, and Summary is only a third wide.

Building it

  • A: drop justify-content: space-between from GameScoreColumn and GameSideColumn, and margin-top: auto from GameOverview's keywords.
  • B: GamePage renders GameRatingsBlock, GameHltbBlock, GameVndbBlock and GameAchievementsBlock boxed in a grid (repeat(auto-fit, minmax(260px, 1fr))), then GameOverview and GameSideColumn with align-items: flex-start. GameScoreColumn goes away. The page counts the score panels on the server (it already does, to hide GameScoreColumn): with one or two, GameSideColumn renders inside the score row and GameOverview spans the width below; with none, the row is skipped. Followings load in the browser and never change the layout.
  • C (shipped): a two-column grid, the sidebar at --game-hero-counters-width plus the hero's padding so it lines up with the counters; stores and links move under the overview as GameLinksPanel, followings get their own panel in the sidebar. At 960px and below it is one column: overview, scores, followings, links.
  • D: columns: 3 with break-inside: avoid on each panel.
  • Below 768px every variant is one column, so the problem and the fix are desktop-only; B's phone order is drawn above. Everything stays in the server HTML.
  • New token if B ships: --mock-stat-panel-min (260px) becomes --game-stat-panel-min-width.

Colours, spacing and radii are the project's own tokens: the :root block above is generated from apps/web/src/lib/app/styles/vars by bun --filter web sync:tokens. The typeface is substituted — Hanken Grotesk stands in for ApercuPro, whose licensed file cannot be served from a third-party host.
