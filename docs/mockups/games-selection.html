Selecting several games at once

The Manage drawer's Controls tab can add every game on the page to Royal, all or nothing. The ask is a Select mode: a switch in Controls that makes the cards pickable, a select-all alongside it, and the picked games going to Royal or to any custom list. Three layouts differ in where the selection lives once it is on — a bar over the grid, the drawer itself, or a tray you assemble. Drawn with the shipped components (Box, Button, Tabs, Checkbox, GameCard, ExpandMenu) and icons from shared/ui/svg.

Where it plugs in

Controls is the first tab of GamesListMenu, inside the right-hand ExpandMenu titled Manage. It holds exactly one button today.

  • Royal already takes a batch — addRoyalGames(ids) from useRoyalGames.
  • Custom lists do not: ListsPanel is built around a single game, so a bulk destination needs a variant of it that takes many ids.
  • Selection is page-local state; the grid is GamesCards and each tile is a GameCard whose bottom row is already occupied by GameControls.
A

Action bar over the grid

Controls keeps one switch. Turning it on puts a Checkbox in the corner of every card and floats a bar above the grid holding the count, select-all and both destinations. The drawer can be closed the whole time — everything you need after flipping the switch is on the page.

Select mode

The drawer in this variant. One ToggleSwitch added; the existing whole-page button stays, because "everything on this page" is still a separate intent from "the four I picked".

  • The destinations are next to the selection, so the drawer never has to be reopened.
  • Costs a row above the grid; on a phone that row wraps to two.
  • The bar must not cover the pagination, which is already fixed to the bottom of the page.
B

Everything in Controls

Nothing new floats over the grid. The Controls tab grows into the whole selection panel — switch, count, select-all, both destinations — and the only change on the page is that a card can be picked. The drawer stays open while you work, which it already does for filtering.

Games

Select mode on, drawer open. The whole-page button drops to the bottom of the panel, where it stops competing with the selection it is not part of.

  • The grid gains nothing but the corner checkbox — no bar, no shifted layout, pagination untouched.
  • The open drawer covers part of the grid on a narrow screen, which is exactly where you are picking.
  • Closing the drawer hides the count and the destinations, so the switch has to stay visible some other way — the checkboxes on the cards are the only hint left.
C

Selection tray

The drawer becomes a tray: picking a card adds a row to it, the same shape the Royal panel already uses. You see what you have gathered rather than a number, and a wrong pick is removed from the tray without hunting for its card. Built for curating a handful, not for sweeping a page.

Select mode on. Unpicked cards dim so the picked set reads at a glance; the tray rows are the same markup the Royal panel uses today.

Choosing the list

Royal is one call. "A custom list" needs a picker, and the one that exists — ListsPanel — is written around a single game. The bulk version keeps its shape: the user's lists with a Checkbox each, a filter once there are more than nine, and inline creation.

Add 4 games to
  • A game already in a list must show as checked and adding again must stay a no-op, the way the per-game panel behaves.
  • Partial state matters: with four games picked and two of them already in a list, the row is neither on nor off. The shared Checkbox has no indeterminate state today — that is a component change to count in.

What building it touches, whichever wins

  • GameCard gains a selectable state. The bottom row is already GameControls, so the mark goes in a corner; in select mode the card's own navigation has to be suppressed or the first pick leaves the page.
  • GamesListMenu gains the switch and keeps addRoyalGames for the batch.
  • The bulk list picker is new: ListsPanel takes one game, and useAddListGameMutation is per game — adding four games to a list is four calls unless the API grows a batch route.
  • Every write to CustomList.games must also set gamesCount; the catalogue filters and sorts on it without reading the array.
  • Selection is not a filter and must not reach the URL — the query string is already the source of truth for what the page shows.
