Game characters

getGameBySlug already looks up the game's characters and sends them with the page, sorted by name, but nothing renders them. Four ways to show them, each drawn in place on the game page. Dashed blocks are the existing sections, the outlined one is new. No character page exists yet, so every variant opens the full profile inside the game page.

A

Portrait rail and drawer

A box between Media and Details with one horizontally scrolling row of portraits, the same rhythm as the screenshot rail above it. A click opens the profile in the shared Drawer on the right, so the page stays in place. Height is fixed at one row whatever the cast size. Characters without a mug shot get their initials.

B

Compact roster with “Show all”

Round avatars with name and species in a dense grid, clamped to two rows by ExpandableBlock; every name stays in the HTML. The least vertical space for a large visual-novel cast, but faces are small and there is no room for descriptions, so a click still opens the drawer.

C

A tab inside Media

No new section: Characters becomes the fourth tab of the existing Media box, next to Screenshots, Artworks and Videos, and uses the same rail. Cheapest on layout, and portraits are pictures of the game like the rest of that box. Hidden by default, so most visitors will not see the cast.

D

List and profile side by side

A box after Details with a scrolling list of names on the left and the selected character's portrait, aliases, facts and description on the right. The only variant that shows a description without a click, which suits visual novels where VNDB descriptions are long. The tallest block, and mostly empty for games whose characters carry only a name.

Block order follows GamePage.tsx: Hero, the Overview · Score · Side row, Media, Details, Related games, Community, then Release dates · Multiplayer. Ghost heights are approximate. Character names and data are sample content; portraits are gradient placeholders.

VNDB descriptions can contain spoilers and VNDB markup. Whichever variant ships, the text goes through RichText, and spoiler handling needs a flag the import does not store today.

Colours, spacing and radii are the project's own tokens, generated from apps/web/src/lib/app/styles/vars by bun --filter web sync:tokens. Hanken Grotesk stands in for ApercuPro.
