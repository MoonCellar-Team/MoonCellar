Content requests

Signed-in users suggest a new game, a correction to an existing one, or a character. Pictures travel as links to other sites, so nothing is stored until a moderator approves. Approval writes the game or character and only then copies the accepted pictures into the Space. Four screens: the request page, the character form, the moderation queue, and a new Characters section of the admin.

Submit
Form with text fields and image links. Stored as a request, status pending.
Review
Moderator sees the current value next to the proposed one and ticks what to apply.
Approve
Game or character is created or updated; ticked image links are downloaded and uploaded to S3.
Notify
The request shows the result on the author's page, with the reason when rejected.
/requests

Request page

One page for both kinds of request. Switches at the top pick Game or Character and Add or Update; the form below changes with them. On the right, the author's own requests with their status and, for rejected ones, the moderator's reason. Try the switches.

/admin · Requests

Moderation queue

A new admin tab next to Games and Reports, with the pending count on it. Queue on the left, filterable by status and kind; the selected request on the right as a field-by-field table of current and proposed values. Every row has a checkbox, so a moderator can take the good part of a request and drop the rest. Image rows say where each file will go in the Space.

/admin · Characters

Characters in the admin

Characters get the same treatment games have: a searchable table with the source of each record, and an editor for the selected one. The portrait can be replaced by upload or by link; the link is copied into the Space on save, like an approved request. Linked games are edited here too, which updates both sides of the relation.

Pictures stay links until approval: the request stores URLs, and the approve step downloads the ticked ones and uploads them with FileService into the existing folders (covers, screenshots, characters). A rejected or withdrawn request leaves nothing in the Space.

An approved update to a game that belongs to a sync should also set the game's stop-parsing flag for the fields it changed, or the next IGDB/VNDB run overwrites the moderator's decision. That rule needs deciding before implementation.

Colours, spacing and radii are the project's own tokens, generated from apps/web/src/lib/app/styles/vars by bun --filter web sync:tokens. Names, links and requests are sample content. Hanken Grotesk stands in for ApercuPro.
