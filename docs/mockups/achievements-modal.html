Option A

Compact list

A plain list where the console is the row's title and the whole row opens the set on retroachievements.org.

  • The game name is dropped: the modal is opened from that game's card.
  • Every row has a 56px icon, greyed out without an award.
  • The award reads as a coloured pill in the card's trophy colours: yellow for mastered, green for beaten.
  • Earned sets sort first, newest award on top.
  • Four rows fit in about the height the current design needs for two.

Needs the API to send each set's imageIcon and numAchievements. Both are already stored in the RetroAchievements games collection.

Option B

Awards first

Built for the profile: what the viewer has earned comes first, and sets without an award shrink to chips.

  • A summary line counts the sets with an award.
  • An earned set is a card with an 88px icon ringed in the award colour, plus the date.
  • Sets without an award become small chips under "Also on".
  • A guest sees only the chips row, under the heading "Available on".

The progress bar needs the viewer's unlocked count per set, which the site does not store today. Without it the bar and the "48 / 48" line are dropped and the rest still works.

Option C

Icon tiles

A grid of set icons, the way RetroAchievements shows them on a profile.

  • The icon is the largest element, so sets are told apart by their art.
  • The award is a corner badge on the tile, and a legend underneath explains the two marks.
  • Holds six to eight sets without scrolling, which suits games with many regional releases.
  • With a single set, the grid would look empty. Option A works better there.

Needs imageIcon for every set, the same API change as Option A.

Icons are placeholders. The real ones are 96px images from media.retroachievements.org, which a published mockup cannot load. Colours, spacing and radii are the project's own tokens: the :root block above is generated from apps/web/src/lib/app/styles/vars by bun --filter web sync:tokens.
