Three Tiptap editor layouts

One component for three places: comments under a game, the review field in the playthrough modal, and later direct messages between users. The options do not differ in what they can do — that part is identical throughout — but in where the toolbar lives and how much room it takes at rest. The fields below are live: press the buttons, select text, drop in an image.

The options are not mutually exclusive: if the base component takes the toolbar layout as a prop (toolbar="fixed" | "bubble" | "collapsible"), A lives in the modal, C in the comment thread, and it is still one component. That costs roughly a day more than a single option, and settles the question before the second use.

Shared

What has to be built either way

  • The icons have to be drawn shared/ui/svg carries no formatting icon, and the project bans @iconify/react along with every other icon library. That is ~10 new Svg* components built on the shared Svg and Path.
  • Image upload already exists filesAPI.uploadFile(file, key, bucketName) is generic — no new endpoint, only the mooncellar-comments bucket. The image host has to join images.remotePatterns in next.config.mjs, or next/image will not render it.
  • The storage format decides the SEO A playthrough's comment is a plain string in Mongoose. Stored as HTML, comments render on the server as they are. Stored as JSON, SSR needs generateHTML from @tiptap/html — otherwise the text never reaches the game page's HTML, which is exactly what docs/seo.md forbids.
  • Sanitising belongs on the backend User HTML cannot be accepted as sent. The schema in packages/schemas has to strip markup down to an allowlist rather than trust the client.
  • Abandoned images A user uploads an image and closes the modal — the file stays in S3. That needs cleanup: either a temporary key prefix and a cron, or deletion through filesAPI.deleteFiles on cancel.
  • The component is client-only Tiptap runs in the browser only. Under apps/web/CLAUDE.md shared primitives carry no "use client" — the editor gets its own client wrapper with dynamic(…, { ssr: false }).

The colours, spacing and radii on this page are not copies but the project's own tokens: the :root block above is generated from apps/web/src/lib/app/styles/vars by bun --filter web sync:tokens. Edit the SCSS, run it again, and this page follows. One exception — the typeface: Hanken Grotesk stands in for ApercuPro, whose licensed file cannot be served from a third-party host.
