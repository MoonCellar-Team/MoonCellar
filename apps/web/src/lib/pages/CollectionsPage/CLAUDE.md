# CollectionsPage

The hub of MoonCellar's own rankings: one link card per generated collection, 53 of them on
2026-11-03. Public, and the entry point to `/collections/<slug>`.

## Routes

- `/collections` — `src/app/collections/page.tsx`.
- `force-dynamic`: a static route would be prerendered at build time with the API unreachable
  and would ship an empty hub. The list itself comes from `unstable_cache`
  (`collections-hub`, 3600 s), and the call site catches a failed request — a throw inside the
  callback would otherwise be cached as "no collections" for an hour.
- Static metadata: title `Collections`, canonical `/collections`, own keywords. The route
  renders `BreadcrumbList` JSON-LD.

## Data

- `collectionsAPI.getAll()` (`GET /collections`) answers every list whose document carries a
  `generator` (`GeneratedListsService`), most games first. Those lists come back with
  `isGenerated: true`, which is what makes `getListHref` point at `/collections/<slug>`.
- No client query: the page receives `collections` as a prop and renders it.

## Composition

1. `BGImage` without a game — the site background.
2. `Box`: `Breadcrumbs` (Home → Collections), the `display` `SectionTitle` as `h1` and the intro
   that says where the order comes from.
3. `Box`: `ListCardsGrid` of `ListCard`s (`isWithAuthor={false}` — the author is the site) or
   `EmptyState` "No collections yet".

## Rules and gotchas

- **Never add `searchParams` to this page.** A filter or a page number would make the hub
  dynamic per request and split 53 collections over URLs nothing links to.
- **The cards stay `ListCard`.** It draws `getListHref`, so a generated list links to
  `/collections/<slug>` and a player's list to its profile URL from the same card; a bespoke
  card here would drift from `/lists`.
- **The intro and the collections' own descriptions say the same thing** about the ranking; the
  description is generated by `GeneratedListsService`, so change the two together if the score
  formula changes.
